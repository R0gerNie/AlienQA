# MVP 01：一般用户预期与认知落差判定

状态：T03 的 N01～N05 工程范围已实现，真实模型效果与完整交付尚待验收。日期：2026-10-01。详见[T03 实施记录](../t03-implementation.md)；父级目标与交付顺序以本目录 README 为准。

本计划服务独立开发者：扫描自己的网页，获得技术异常与违反一般用户认知的可核对线索。
默认用户只有一个定义：第一次使用本产品，具备通用网页操作经验，未接受本产品培训。
预期依据来自界面表达、通用交互惯例和本次使用中已经看见的行为；不建立岗位、行业或企业画像。
输出是待审阅的认知落差，开发者可以采信、拒绝或暂缓；“按设计”不自动证明用户能够理解。

## 1. 实施前能力与需要修订的依据

本节保留计划提出时的事实与质问；T03 已隔离源码简介/范围指令并接入可见历史，当前边界与验证见实施记录。

已核对原 [03 上下文计划](../../planbooks/03-exploration-context.md)、[08 预期计划](../../planbooks/08-expectation-engine.md) 及对应源码。

| 当前已经实现 | 本计划尚未实现 |
|---|---|
| `Pipeline.collect` 在执行前调用 `expect(..., action=action)`，预期绑定当前动作 | 为每条预期保留可核对的依据和来源 |
| `evaluate` 区分 passed、mismatch、failed、inconclusive | 控制互相冲突、过度具体或无法观察的预期 |
| `ExplorerContext` 只输出白名单字段；调查上下文独立 | 源码导出的 brief、原始 focus 不再变相提供“正确答案” |
| 上下文已经组装动作历史；判定使用执行前后截图 | 预期阶段真正消费有边界的近期可见行为与结果 |
| 预期阶段消费页面文字、元素描述及动作 | 普通用户定位的固定回归及真实模型效果验证 |

字段裁剪不等于语义隔离。当前 `Mapper` 可读取 README 和源码片段，`product_brief` 可能携带内部规则；
`ExpectationEngine.focus` 直接进入提示词，单元定位摘要也会追加进入。上述输入边界目前尚未消除。
当前预期生成没有消费截图或历史；本计划先补必要文本历史，视觉预期增强由效果验证决定，不强制更换视觉 API。

### J-C01：源码摘要和测试指令可能提前提供答案（P1）

组员质问：如果 README 写着“删除后不会消失”，或指令写着“保存本来就没有反馈”，外星人还在检验一般用户理解吗？

作者最佳回应（原 03 §4）：“单一出口：只有本模块能拼装 Explorer 上下文。”“白名单过滤：按字段白名单裁剪，黑名单项永不进入上下文。”

检查：引文占比达标（回应正文全部为引文）；事实一致性通过（原文承诺）；对挑战的回应部分充分。
仍需追问：允许字段内部的规则由什么可见证据支撑？当前代码中的原始 focus 如何被这一出口约束？
判断：边界定义缺口与实现落差成立，可能把产品内部答案当作自然预期。J01、J02 关闭此项。

### J-C02：发散预期可能把一种实现偏好放大成缺陷（P1）

组员质问：保存有明确状态变化，但没有 toast，为什么采样出的“必须弹成功提示”应成为不符？

作者最佳回应（原 08 §4）：“高温度采样取并集：同一动作采样 2~3 次，合并预期集合，鼓励发散。”
“只产出 Mismatch，禁止定性 Bug：Bug 的定性留给 09/11/12。”

检查：引文占比达标（回应正文全部为引文）；事实一致性通过（原文承诺）；对挑战的回应部分充分。
仍需追问：人能拒绝错误预期，但为何让无依据的表达占用有限执行预算与审阅时间？
判断：合理性与发散控制尚需补充；保留发现能力，合并等价预期并接受多种有效反馈。J03、J04 关闭此项。

## 2. 输入、输出及共享契约

输入：动作执行前的可见文字与可访问名称、可见控件状态、当前选定动作、近期已完成动作及可见结果。
范围输入：单元名称、路径或扫描边界只用于定位和候选过滤；自由文本指令不进入预期生成提示词。
产品理解：从浏览器可见信息形成粗略介绍；缺少依据时保留未知，不使用源码摘要补成业务规则。
禁入：PRD、源码、README 的内部说明、调查结果、已知问题、动作之后才出现的结果。

输出：动作绑定的预期候选、依据引用、判定状态；不符继续交给证据与审核计划，不符不自动等于 Bug。
以下是未来接口设计，本文不改当前 schema；落地前与父级共享契约及证据计划统一：

| 字段 | 拟议语义 |
|---|---|
| `finding_kind` | `technical_anomaly` 或 `cognitive_mismatch`；运行器失败与模型诊断另列 |
| `expectation_basis.type` | `visible_copy`、`interaction_convention` 或 `observed_behavior` |
| `expectation_basis.reference` | 用户可核对的文案、惯例描述或已完成步骤引用文本 |
| 审核状态 | 沿用现有 `Decision`，不增设一套预期审核状态 |

`expectation_basis` 是各条 `Expectation` 及对应 `Evidence` 的单个 `{type, reference}` 对象，与该条预期原文对应。
`cognitive_mismatch` 必须采用上述三种依据类型；`technical_anomaly` 来自动作窗口内确定性运行信号，basis 为 null。
沿用旧 `Evidence` 作为实体，不新增 finding 存储；两类都只是候选，均不自动定性为已确认 Bug。
旧证据没有 basis 时显示“旧记录未提供依据”，不得补造出处或推断来源；旧文件允许缺少新增字段，新记录按类型校验。
依据是生成时的主张，不是合理性已被证明；行业惯例不能伪装成“一般用户普遍知道”。

## 3. 工程任务

### J01：固定默认用户与预期输入边界

- 修改 `alienqa/context/models.py`、`assembler.py`、`pipeline.py`，明确浏览器可见预期输入与探索定位输入的分工。
- 源码模式仍可通过 Product Map 帮助寻找入口；预期侧不消费源码派生 brief 和导航规则，缺少可见介绍即可为空。
- 保留源码用于后续调查；不以禁用源码模式代替输入隔离。控件的内部 selector 用于绑定，不作为用户认知依据。
- 验收：同一页面、动作和可见历史保持不变，只修改仓库内部规则，捕获的预期请求内容保持不变。
- 验收：页面公开说明修改后，请求中能看到新说明及其可见出处；没有介绍的页面仍可生成动作级预期。

### J02：扫描范围与自由文本指令不提供正确答案

- 修改 `pipeline.py` 的 `_join_focus`、`ExpectationEngine.focus` 消费路径和 `llm/roles.py` 的 `generate_expectations`。
- MVP 推荐保留自由文本给定位器使用，预期模型只接收过滤后的可见候选及选定动作；不把定位摘要直接追加进预期 prompt。
- 单元定位不得扩大扫描范围；无法定位沿用 `scope_not_found`。CLI/UI 说明指令用于范围，不提供预期正确答案。
- 验收：指令含“保存不用反馈，默认算成功”时，预期请求不含该句，实际缺少反馈的判断仍依据界面。
- 验收：指定设置单元后仅执行范围内动作；范围内没有可用动作时保留诊断，不输出“全部通过”。

### J03：候选预期保留依据并控制发散

- 修改 `expectation/models.py`、`engine.py`、`llm/roles.py`；按共享契约增加可选 basis，严格校验新输出及旧格式兼容。
- 先要求效果层表述，例如“用户能确认保存结果”；toast、状态更新、跳转等可替代反馈不拆成互相强制的预期。
- 合并同义或互斥候选；只保留当前动作能验证、拥有依据的预期，空集合保持 inconclusive。
- 建议默认每动作最多 3 条独立预期，作为内部预算；该值需在小样本效果验证中确认，不增加 MVP 配置面板。
- 不以多次采样次数作为置信度，不通过“提高严重度”补偿证据不足，不要求唯一成功呈现形式。
- 验收：重复的“toast/成功文字/状态已保存”合并为效果级预期；不同反馈实现满足同一预期。
- 验收：模型输出未知依据类型、空出处或期待后台字段变化时明确拒收或记录解析失败，不成为不符证据。
- 验收：旧 `Expectation(text, action_desc)` 调用仍可用，旧报告可以打开且不会被伪造来源。

### J04：让先前可见行为形成有限的用户经验

- 修改 `context/assembler.py`、`expectation/engine.py` 与 `pipeline.py`；从已完成步骤选择近期动作和可见结果摘要。
- 仅动作名不足以证明 observed_behavior；引用应能对应已保存步骤与其用户可见结果，缺少结果时不得推断。
- 按现有上下文预算截断，保留步骤引用；截图、技术日志和调查解释不混入此文本历史。
- 每步先冻结预期输入，再执行动作，再保存观察；本次结果仅能成为下一步历史，不能回写本步预期。
- 验收：前一步已有“删除后列表移除”的可见结果，下一步能引用该经验；未发生的动作及最终页状态不出现。
- 验收：返回旧页面仍保留真实访问顺序；截断后引用只指向保留下来的步骤，空历史不冒充使用经验。

### J05：合理例外与无法判断的结果规则

- 修改候选描述及 `llm/roles.py` 判定提示，必要时联动 `driver`、`observation`，传递可见禁用、只读、必填和反馈状态。
- 合法禁用且原因可理解，不期待点击生效；已执行动作导致无理由禁用时，可基于该动作的事前预期与实际结果产生线索。
- 初始页的禁用元素作为可见上下文，不尝试强行点击，不为它伪造一次成功动作；MVP 不增加独立静态界面审计通道。
- 输入非法值时，验证提示或阻止提交可以是合理结果；网络加载尚未结束、遮挡或观察不足沿用 inconclusive。
- 动作执行失败、模型失败、结构无效属于扫描诊断；技术异常单独分类，不为它临时构造认知预期。
- Mapper 或预期模型失败时，认知路径标无法判定；已有浏览器确定性候选仍允许技术 QA 执行和采证，不在事后补生成预期。
- 与兄弟 R02 解耦动作窗口 runtime 采集与 LLM 视觉/判定：认知模型失败、basis 拒收或视觉失败，不阻断技术异常独立落盘。
- 验收：空必填提交出现清楚验证提示，不因“没保存”报不符；可见有效输入提交无反馈进入待审阅落差。
- 验收：清楚禁用上下文、动作后无解释禁用、遮挡、模型坏 JSON 各自按其事前预期和可观察证据判断；没有执行的禁用控件不计为通过。
- 验收：预期生成失败后仍能采集该动作的新 pageerror，并产出 basis=null 的技术候选和认知诊断；不出现事后预期。

### J06：用固定反例与真实模型检查默认认知

- 在 `tests/test_exploration_context.py`、`test_expectation_engine.py`、`test_pipeline_regressions.py` 建立输入与状态契约回归。
- 增加小型可运行网页夹具：等价保存反馈、必填验证、清楚禁用、无理由禁用、前后行为不一致；采用真实浏览器采证。
- 测试替身验证边界与流程；真实模型抽样验证预期是否有据、例外是否被理解，结果交给效果验证计划，二者分别报告。
- 每个场景保留预期请求、输出、观察、审核决定及拒绝理由；不以“产出不符越多”作为验收目标。
- 验收：独立开发者能从依据和前后观察解释每条线索，并拒绝错误预期；模型故障记录可与产品落差分开查看。

## 4. 依赖、时序与集成完成条件

J01、J02 可并行开发，先固定预期输入；J03 依赖父级共享契约，J04 依赖步骤中可见结果的保存。
J05 与 J03 可并行准备夹具；J06 消费全部任务的产出。
与 [02 证据与报告](02-findings-review-report.md) Rxx 对接类别和 basis，与 [03 本地运行](03-local-run-and-delivery.md) Lxx 对接故障继续采证，
由 [04 验证发布](04-validation-and-release.md) Vxx 消费场景和结果；共享字段只按父级 [README](README.md) 定义。
运行时顺序必须为：动作选择 → 输入快照与事前预期 → 执行 → 原始步骤/runtime 先落盘 → 可见观察落盘 → 视觉/认知判定 → 增量保存 → 后续步骤消费历史。
认知模型阻塞或被终止时，原始技术记录已存在；认知结果保持未完成，不从已保存技术候选推导 passed。
超时或取消后未完成的观察不得进入历史；重放结果不得倒灌原始预期；重审改变 Decision，不覆盖生成时依据。
完成条件：一次 URL 扫描能输出带依据的认知线索、独立技术异常和扫描诊断，旧文件兼容，固定反例通过。
该完成条件验证功能 MVP；真实用户接受率与模型费用仍需效果验证，不宣称已证明代表所有一般用户。
