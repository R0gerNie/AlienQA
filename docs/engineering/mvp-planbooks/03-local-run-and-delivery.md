# MVP 03：独立开发者本地运行与交付

版本：2026-10-02。状态：L01～L05 功能 MVP 经 T04/T05/T06/T07 接通，本机真实 worker 与安装包路径已验收；T01 深入识别、T09 新环境及真实应用效果仍开放。见 [T07 实施记录](../t07-implementation.md)。共享规则见 [父级 README](README.md)。
目标是让一个独立开发者完成 URL 输入、扫描、看证据、回放、记录决定和 HTML 留存。
复用当前 CLI、Flask 控制台、目录/SQLite 及单任务进程控制，不建设岗位配置、账号、团队队列或部署平台。

## 1. 已有机制与新增缺口

已核对 `__main__.py`、`pipeline.py`、`ui/app.py`、`ui/runs.py`、`ui/jobs.py` 及既有回归。

| 已有机制，可直接复用 | 本计划待完成的整合 |
|---|---|
| URL、源码+URL、登录态与静态服务输入 | 默认 URL 的简洁入口、范围指令用途和分析结果入口 |
| UI JobController 单任务占用、停止/超时进程树回收 | 技术采证不被认知/地图/调查模型故障阻断 |
| scan.json、证据、调查、review.json 和回放包 | 一般用户版本、输入快照与实际扫描范围的可核对摘要 |
| running/done/partial/error/timeout/cancelled 等 run 状态 | 将执行完成、认知判定完成与发现数量分别呈现 |
| 历史读取、审核后报告失效、回放结果持久化 | analysis/confirmed 两种入口与快照消费的一致性 |

现有 CLI 时间预算主要在动作边界检查，UI 有整任务进程超时控制。
本计划不把动作边界预算描述成可中断任意阻塞调用的硬超时；两种时限在界面和文档中分别说明。

## 2. 输入输出与交接

输入：运行 URL（默认）、可选登录态、可选扫描单元、动作与时间预算、本机模型配置。
源码/静态目录和 CLI 显式启动命令沿用现有能力，放在高级入口；不自动安装或启动未知框架的后端服务。
输出：run 状态、步骤、终止原因、诊断、完整证据及回放包；报告交给 [MVP-02](02-findings-review-report.md)。
一般用户输入与源码查因的边界由 [MVP-01](01-general-user-judgment.md) 决定；用量与发布证据由 [MVP-04](04-validation-and-release.md) 消费。

保留现有 run 状态字段。完成一次有预算的扫描不表示覆盖全站；模型不可判时可返回 partial，并保留技术候选。
达到预定动作预算只表示本次有限扫描结束，stop_reason 保留预算原因，不自动等同于执行错误；未判定步骤与故障另计。
报告只消费终止后的有效扫描结果；运行中显示进度和已有步骤，不生成会被后续写入改变的正式 HTML。

## 3. 工程任务

### L01：默认 URL 到分析的入口

- 修改 `ui/templates/index.html`、`run.html`、`ui/app.py`、`__main__.py` 和使用说明。
- 首页主要输入为 URL；登录态、范围和预算可选，复用设置页，不要求选择岗位或填写正确答案。
- 源码目录用于辅助查因；扫描范围说明明确区分“只看设置页”与内部业务规范。
- 将已完成 run 的主要结果入口接到 analysis；confirmed 导出保持明确名称，自动采信仍是显式演示选项。
- 验收：仅有运行 URL 和有效模型设置可启动；没有源码的路径能够完成分析与 HTML 保存。
- 验收：范围为空时正常扫描，无法定位指定单元时明确诊断，不悄悄扩大为全站。

### L02：启动前校验与可解释的失败

- 复用 loader 和配置校验，检查 URL 格式/可达、登录态文件可读且结构有效、正数预算和模型配置必需项。
- 配置检查不默认发付费探测请求；真正供应商调用的异常进入 V02 的 attempt 记录。
- URL 不可达、应用启动失败、会话文件无效应分别说明；能打开但进入登录页时记录真实页面，不能猜测扫描已登录业务范围。
- 环境阻塞不会生成“未发现问题”的成功结果；已有产物可保留，后续模型阶段不得使用不存在的登录前提。
- 验收：不可达 URL、坏 session JSON、缺模型设置各给具体原因；不得进入误导性空报告。
- 验收：运行遇到登录跳转，报告说明实际访问到的页面；不把未进入业务页算作业务流程验证完成。

### L03：技术采集与模型阶段解耦

- 修改 `pipeline.py`、`observation/engine.py`、`ui/app.py`，复用现有 driver 的 runtime 快照与原始收集。
- 固定事件顺序为：当前状态/候选 → 事前预期尝试 → 执行 → 原始步骤/runtime 立即保存 → 截图/可见结果保存 → 视觉与认知判定 → 增量更新。
- 浏览器进入页面后先保存入口异常，再尝试产品地图；复用现有原子 JSON 写入/证据持久化，已保存前缀可由终止后的分析读取，不引入消息队列。
- 与 R02 共同保证技术异常独立保存；预期失败仍允许已有确定性候选继续执行，认知步骤明确未完成。
- 产品地图失败时允许浏览器可见候选的技术路径继续，标记地图/认知降级；不得用伪造 brief 填补故障。
- 调查失败保留候选和诊断，不能使分析页或报告消失；本次执行后不得补造事前预期。
- action 执行失败、截图/观察不足、模型错误分别记录；步骤中的执行结果与判断结果不能互相覆盖。
- 完成状态区分执行数量、有效判定数量、技术候选数、认知候选数和未判数量；无候选不自动计作通过。
- 复用 UI 的 single-slot JobController；停止/超时后确认退出再释放占用，迟到完成不能覆盖 cancelled/timeout。
- 验收：预期或视觉模型故障与真实 pageerror 同时发生，技术候选、原始信号及不完整诊断都能打开。
- 验收：停止、超时、执行失败后不会出现迟到 done；下一次合法扫描在资源回收后可启动。
- 验收：原始 pageerror 保存后模型阻塞并被终止，历史中仍有步骤/技术证据；判定部分显示未完成，坏写入不能变成伪空列表。
- 验收：技术降级扫描没有认知判定成功计数，不能从技术执行成功推导一般用户检查通过。

### L04：运行摘要、历史与回放接线

- 复用 `PipelineResult.save`、`RunManager.save_diagnostics/save_results`，保存输入模式、URL、预算、终止原因与模型/prompt 版本摘要。
- 为已完成步骤保存有边界的实际可见文字结果或截图引用，供 J04 引用 observed_behavior；不拿调查结论或技术日志补作用户经验。
- 历史页从实际保存步骤统计覆盖和未完成数量，不由最终 Issue 数量推导扫描质量。
- 复用 replay 起点、storage_state、成功动作前缀与静态服务目录/端口元数据；保存结果，原始证据不被覆盖。
- 元数据引用本机 session 文件或回放包；独立报告不包含凭据内容，不引入新的集中凭据管理系统。
- 验收：重启控制台仍可查看已落盘扫描、决定与回放结果；损坏或缺少产物显示明确缺失，不伪造完成。
- 验收：跨页面前置动作可在新上下文回放；关闭的静态服务按记录恢复，端口冲突或目录缺失显示失败。

### L05：单人整体验收与说明

- 用真实浏览器和固定模型替身验证 URL → 扫描 → 两类发现 → 回放 → 决定 → analysis HTML。
- 使用已有 CLI/UI 测试扩展边界场景；真实 worker 与浏览器控件验证分别记录，避免 UI 替代 worker 被称为完整模型执行。
- 与 R05 复用现有本机锁，生成报告时取同一 run 的终态结果和审核快照；决定变化后两种缓存报告均失效。
- CLI 与 UI 的默认分析入口遵循同一模式，不添加岗位表单、组织选择或外部发布步骤。
- 更新 README 的当前能力与示例；计划中的新 mode 不提前写成现有可用参数。
- 验收：另一个目录打开 HTML 可核对截图、原始观察、决定及限制；工具退出后已保存内容仍可读。
- 验收：模型失败、全部拒绝、按设计保留、未审和零发现各有清楚结果，不共同显示“产品通过”。

## 4. 依赖与完成定义

L01、L02 可与 J/R 并行；L03 与 J05、R02 必须共同验收，不能只靠三个模块单测通过。
L04 消费已有存储并与 R05/R06 的报告数据对接；L05 是父级用户路径的整体验收。
V01 样例与 V02 计量可以先准备；真实模型和小应用验证消费上述路径，不等待大型框架环境全部完成。

完成时，独立开发者只需已有可运行页面、本机配置和必要会话，即可获得可解释、可回放、可保存的分析结果。
用户可以停止任务、辨认检查未完成的原因并继续审阅已有证据；无需企业配置或重建项目运行环境。
本计划只描述待实施工程，先前 302 项回归不能代替本计划新增交接的验收。
