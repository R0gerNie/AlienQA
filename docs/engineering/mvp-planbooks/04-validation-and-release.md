## 1. 本节点负责的结果与依赖

让独立开发者知道：工具能发现哪些技术问题和认知摩擦，发现链路是否丢失候选、模型调用成本是多少，在哪些环境已验证可用。首个可用版本以本地 URL 扫描、审核和自包含 HTML 报告为闭环，不以三框架复杂仓库广覆盖或 PDF 为前置。

依赖 [J：一般用户认知判断](01-general-user-judgment.md)、[R：发现、审核与报告](02-findings-review-report.md)、[L：本地运行与交付](03-local-run-and-delivery.md) 及 [共享契约](README.md)。这里验证它们能否组合成立，不重新设计这些接口。技术异常与认知摩擦分列；`by-design` 只表示团队选择保留设计，不能自动抹去合理的用户预期。

认知预期与证据使用共享的单一 `expectation_basis={type,reference}`；独立确定性运行时异常候选使用 `expectation_basis=null`。`Decision` 继续作为人工处理状态，runner 诊断单列。效果标注属于评估侧，不给产品接口增加另一套决定枚举。

已知答案、标注理由与故障注入设置保存在评估侧，不能进入产品简介、探索指令、预期生成或判定提示词。扫描目标只能收到真实用户可获得的信息。源码调查可在产生证据之后进行，调查结论不能倒灌到本轮预期。

## 3. V01：针对功能的样例与测试层次

复用 `tests/fixtures/` 已有表单、状态、回放样例，按缺口增补。每个样例说明初始状态、可达操作、正常与异常版本、重置方法及评估侧标注；相同路径应有正常或合理例外对照。

首批样例建议为 6 类交互、每类至少一组配对：此数量是起步建议，不是已批准规模或对外覆盖承诺。

| 交互 | 可疑版本 | 正常或合理例外对照 |
|---|---|---|
| 保存与异步反馈 | 点击后长期没有结果线索 | 明确保存成功；保存中有反馈 |
| 表单校验 | 必填失败却没有可理解解释 | 字段错误可定位；提交前合法禁用 |
| 删除与取消 | 取消仍删除；文案与动作对象不一致 | 确认删除；取消后保留对象 |
| 空态与筛选 | 无结果被显示成故障或无限加载 | 清晰空态；能清除筛选恢复列表 |
| 弹层与导航 | 打开空弹层；返回丢失关键上下文 | 可关闭弹层；明确的登录跳转 |
| 技术故障 | JS 异常、关键请求失败或白屏 | 非关键失败有可解释降级，核心任务仍可完成 |

测试分三层，并分别报告，避免用总测试数量代替效果结论：

1. **确定性契约测试**：模拟模型验证动作前预期、动作绑定、schema、失败/无法判断、范围输入、角色信息边界；验证 `basis`、独立技术异常候选及五态审核。`analysis` HTML 保留全部证据、未决和备注；`confirmed` 兼容已有严格 gate。已有测试可扩展，不复制实现写无意义断言。
2. **真实浏览器链路**：模拟模型配合 Chromium，走填表/勾选/提交、modal、路由、登录态、保存证据、独立回放、重审后报告更新、停止/超时。必须核对原始动作和截图来自同一次交互，并验证技术信号先保存后模型阻塞被终止时仍可读取原始证据。
3. **真实模型效果**：使用相同样例和冻结配置，由模型自行形成预期并判断，记录全部发现、覆盖、未处理项、波动和成本；正常/例外不预设零发现；不能由 stub 提供答案。

默认测试继续自包含，不要求 API 密钥和外部克隆仓库。真实模型评估为显式命令，必须先显示目标、配置和调用预算；测试执行者主动启用。大型外部基线保留 opt-in，未执行不算失败，也不能宣称已验证。

## 4. V02：计量当前缺口与最小实现

实施前 `LLMResponse.usage` 只返回成功响应中的 usage，失败尝试没有持久化。T08 现已记录六角色每个逻辑调用及逐次 fallback attempt，解析失败另列；运行、角色与实际模型汇总由明细重算，缺 usage/费用及停止后未返回请求均明确为未知。可选 reporter 也归属原 run。当前只接受明确的供应商费用适配字段，不启用未经验证的库内价格估算；这不代表已有真实供应商结算或费用硬上限。

最小实现是在每次实际供应商调用周围记录 attempt，不新建收费、账户或配额系统：

- 关联字段：`run_id/step_id/call_id/attempt_index/role/model`，实际模型、配置和 prompt 版本；没有 step 的 gist/report 调用也归属 run。
- 状态与时间：开始、结束、耗时、成功/失败/取消/未知；异常类型与可读原因，fallback 关系；worker 被终止时允许保留未闭合 attempt 并显式标记未知。
- 用量与费用：供应商原始 usage、可识别输入/输出 token、费用金额/币种/来源；估算注明价格快照日期和公式。失败调用可能被收费；供应商未返回时标未知，不推定免费。
- 存储与汇总：本地追加明细及 `usage-summary.json`；覆盖 gist、expectation、visual、judge、investigator、reporter，包含重试和 fallback，汇总未知项数量。
- 输入审计：保留允许的角色输入与输出引用，便于核对污染和判据；不把 API key、完整登录态或会话凭据写入公开评估结果。私有原始记录与可分享摘要分开保存。

计量回归至少覆盖“主模型成功”“主模型失败后 fallback 成功”“全部失败”“usage 缺失”“停止时 attempt 未完成”。汇总必须能与明细逐项对上；未知费用不能混入精确总价。费用上限执行若尚未实现，应写明当前只有动作/时间限制和人工调用预算。

## 5. V03：最小真实应用基线

选择一款真实的独立开发者小应用，以已运行 URL 接入；开发者提供其固定版本、可重复的任务和数据重置方式。无需先证明 React/Vue/Next.js 三框架复杂仓库全部支持。源码调查可作为可选补充，不阻塞 URL 路径的发现与报告。

首轮建议使用一套明确模型配置，固定样例与任务各重复 3 次，用于观察波动；这是建议量，不是统计显著性承诺。调用额度由执行者在运行前确定。资金或环境不足时可缩减规模，并保留缩减后的分母，不能挑出成功 run 当全集。

每轮 manifest 固定应用版本、数据种子/会话私有引用、初始 URL、视口、任务范围、动作与时间预算、预期采样数、模型/温度/fallback、prompt 版本、样例版本和重复序号。异常注入与标注答案另存于评估侧；原始 run、attempt、截图、判定、回放和审核决定先保存，再生成汇总。

受控技术故障可以用运行断言核对是否采集、是否遗漏；不能把内部实现答案作为认知发现的正确性判据。认知预期由模型形成，所有结构有效且来源可关联的发现保留。用户采信、拒绝、按设计或暂缓是使用时的选择，不是验收员批准。

独立人审、认知有效性、误报率、正常对照投诉上限和审阅分钟全部撤销为必过项。已有反馈模板保留为可选工具，未收集时分钟未知，不填零。analysis 全证据集作为传递核对输入，confirmed 不作为总体分母。

| 指标 | 核对口径 | 必须披露 |
|---|---|---|
| 探索覆盖 | 已访问状态/已尝试动作，对照冻结任务中的已知可达路径 | 未探索、预算结束、环境受阻；不冒充全站覆盖 |
| 候选保留 | 全部合法采样成员是否有代表及冻结 ID，代表是否进入 judge | 等价去重成员、单次出现、分歧保留、坏 schema、失败及弃权 |
| 发现交付 | judge 报出的落差是否都有 Evidence 并在 analysis 可见 | ID/text/basis、原始采集引用、所有用户 Decision 均不删除原发现 |
| 局部未知 | 已判断要求与无法判断要求同时列出 | 不因未知抹掉其他落差；未处理和无观察不伪装成通过 |
| 回放与复现 | 原观察条件/信号是否再次出现 | failed/inconclusive 与环境受阻；不作为认知合理性裁判 |
| 调用成本 | 每 run/角色全部 attempt、token、已知费用与未知项 | 失败/重试/fallback，未知不填零，不以人工采信数作为费用分母 |
| 可选用户反馈 | 用户自己选择记录的决定、体验和分钟 | 无需独立审阅，不影响验收或发布，无接受率/误报门槛 |

先保存完整基线，再依据实际未探索、候选丢失和采集缺口冻结下一轮工程复测门槛。费用和调用预算按真实记录确定；不以高发现数证明普遍用户认知，也不因模型主观怀疑与内部答案不同而判失败。

## 6. V04/V05：本地发布边界

首批 smoke 从历史已验证的本机 macOS / Python 3.11 / Chromium 组合开始，在第二个干净虚拟环境安装 wheel，核对配置与模板随包可用、依赖检查、浏览器安装、URL 扫描、登录态、停止、回放、审核保存、重审、HTML 离开原目录仍可读。真实模型 smoke 保持显式启用，离线 smoke 不能替代它。

GitHub Actions 已取得 Ubuntu / Python 3.11、3.13 默认回归与 3.11 干净安装的远程证据，见兼容/发布记录；这不替代当前改动的 CI。CI 通过后再据结果扩展支持矩阵；Windows、Firefox/WebKit、其他 Python 组合先列未验证，不把全平台矩阵设为首个 MVP 的硬门槛。一次构建成功也不能替代从发行包安装后的端到端 smoke。

发布说明必须区分确定性回归、真实浏览器、真实模型评估和用户试用，记录版本、支持组合、已知问题、数据/登录态保管说明及回放前置条件。公开摘要不携带凭据；局部扫描与未完成 run 不得被宣传为全站通过 QA。

本节点延期项：大型三框架仓库广覆盖、岗位/行业画像配置、PDF 排版、自动工单投递、多人队列与权限、SaaS 和商业化。保留原长期计划，不让这些能力成为独立开发者拿到首份有用 HTML 的前置。

## 7. 节点关闭与下一轮输入

关闭本节点需要 V01 契约全部通过、V02 账目可核对、V03 首轮基线及下一轮覆盖/候选保留门槛记录、V04 一条完整发行包 smoke、V05 支持与限制说明。只有文档或 mock 通过时保持“计划/机制已验证”；真实模型证据不足则标为实验性版本，不声明已达到未知的效果门槛。
