# AlienQA 下一阶段工程计划：独立开发者的功能 MVP

版本：2026-10-01-mvp-4。状态：T04 与 T03 工程范围已落地；真实模型与功能 MVP 闭环继续验收。
本版采用用户当前明确的定位：独立开发者用 AlienQA 做 QA，并分析交互是否违反一般用户认知。
工程执行入口为 [功能 MVP Planbook 组](mvp-planbooks/README.md)，具体模块/框架兼容、接口和验收见[九份技术子计划](mvp-planbooks/technical/README.md)。[上一版计划](archive/2026-10-01-next-stage-before-mvp.md) 保留历史审查与验证材料。

## 1. 定位与本轮变化

外星人默认具备通用网页操作经验，第一次使用目标产品，不知道该产品的内部约定。
工具交付技术异常与认知落差的证据，帮助开发者解释、复现、决定如何处理并留存分析。
一般交互的依据来自可见表达、交互惯例和先前看见的行为；不把模型预期当成业务规范，也不以“按设计”自动消除用户困惑。

用户已经给定两个约束：“先做功能层MVP”；“一个独立开发者可以使用这个项目作为QA和分析是否违反一般用户认知”。
据此暂不建设岗位/行业画像、persona 配置、组织权限或团队服务。单人工作流就是本阶段的完整产品结果。

核心用户路径：运行 URL → 有预算的探索 → 事前预期与实际证据 → 技术/认知候选及诊断 → 开发者决定和备注 → 完整 analysis HTML。
源码、调查假设和 confirmed 缺陷报告保留现有入口，作为辅助能力；HTML 先交付，PDF 后置。

## 2. 为什么调整推进顺序

| 上一版主要安排 | 当前推荐顺序 | 原因 |
|---|---|---|
| 三种框架的大型真实候选与效果 gate 在完整审阅交付之前 | 一般用户判定、技术采证和 analysis 报告先形成可用闭环，小规模真实模型同步验证 | 独立开发者先需要可理解、可留存的结果；大型部署成本不应阻断功能 MVP |
| 审核主要服务 confirmed-only 的缺陷终稿 | 完整分析为主入口，已有 confirmed 视图保持兼容 | “按设计”“待审”“暂缓”也包含用户认知信息，需要留下观察和开发者判断 |
| intuition/guided 模式定义作为待决策项 | 默认一般用户模式，原始自由文本仅用于扫描定位；guided 平台后置 | 不增加新模式配置和预期答案输入，先保持认知判断的来源可解释 |
| HTML/PDF 和复杂 Issue 审阅作为下一阶段整体交付 | Evidence 复核、四种决定与备注、单文件 HTML 先做 | 保存和理解发现是单人 MVP 必需；PDF、手工合并拆分可在试用后判断收益 |
| 较广的发布与框架支持矩阵 | 先验证一个明确的本地组合和小应用，再逐项扩展 | 发布支持范围由运行证据决定，不把未运行平台写成已支持 |

保留已有可靠性工作：动作绑定、失败可见、成功动作轨迹、回放、Issue 调查隔离、停止回收和缓存失效。
不重新开发已经通过确定性回归的基础机制；新增任务针对当前定位尚缺的功能和交接。

## 3. 主要工程计划及依赖

| 节点 | 主要工作 | 交付给下游 | 集成验收 |
|---|---|---|---|
| [MVP-01 一般用户判定](mvp-planbooks/01-general-user-judgment.md) | 控制输入来源，记录预期依据，消费实际可见历史，处理合理例外与未知 | 事前预期、basis、判定、认知候选 | 只改内部规则不改变固定可见输入；等价反馈和合理校验不被固定判错 |
| [MVP-02 发现与报告](mvp-planbooks/02-findings-review-report.md) | 技术原始采证与模型解耦；四种处理决定和备注；analysis 与 confirmed 分工 | 全量证据、原声、决定、HTML | 模型故障仍保留 pageerror；按设计/未审有明确状态且不会在 analysis 消失 |
| [MVP-03 本地运行](mvp-planbooks/03-local-run-and-delivery.md) | URL 主入口、校验、失败降级、终态快照、历史与回放 | 输入、步骤、终止原因和完整产物 | 单人从 URL 到可复制 HTML，停止后无迟到成功，缺产物明确提示 |
| [MVP-04 验证发布](mvp-planbooks/04-validation-and-release.md) | 配对样例、attempt 计量、一款真实小应用、小规模模型基线和安装 smoke | 效果/成本证据、支持范围和试用材料 | 每类指标有分母，失败/fallback 不漏记，真实用户认知线索可被开发者核对 |

共享契约只定义一次，见 [MVP 索引 §4](mvp-planbooks/README.md#4-共享契约只做必要的增量)。
沿用 Evidence/ReviewState/RunRecord 与既有存储，增量添加 finding_kind 和 expectation_basis；旧文件不补造新依据。
分析报告消费终态扫描与一致的审核快照；模型观察失败不影响原始技术证据，开发者重审不覆盖外星人的原始预期。

MVP-01/02/03 可并行实现；接口和状态规则先对齐。MVP-04 的样例与计量同时准备，有可运行闭环后立即做真实模型抽样。
运行时保持：预期在执行前；执行后先持久化原始步骤/runtime/技术候选，再尝试视觉和认知并增量保存；保存证据后才供报告、回放和调查消费；本次结果只用于下一步历史。
入口信号同样先于地图模型保存；模型阻塞时被停止，已保存技术证据仍可进入分析，认知部分标未完成。

## 4. 阶段闸门

| 阶段 | 结果 | 验收边界 |
|---|---|---|
| M0：定位与契约 | 当前用户、范围和子计划交接清楚 | 本轮文档已经给出；不代表新代码已落地 |
| M1：功能核心 | J/R/L 主路径可用，两类候选和分析结果可读 | 定向 fixture 与模型替身验功能；真实模型尽早开始，原始证据不由模型成功单点决定 |
| M2：小规模可用验证 | 完整单人闭环、调用计量与一款小应用真实模型基线 | 分别报告技术命中和认知合理性，不以 by-design 自动计为误报；模型故障计入未完成 |
| M3：单人试用发布 | 干净安装、旧文件可读、HTML 移交、支持范围说明 | 独立开发者能完成扫描、核对、决定和留存；工期与效果数字从实际执行取得 |

首批样例数、真实模型重复次数为子计划建议值，执行前固定；未测得的发现率、误报率、成本或发布日期不填写承诺。
首次真实模型执行先形成基线，再选择后续改进阈值；严格的确定性数据/时序契约须全部通过。
复杂框架部署、广泛模型矩阵、PDF 和团队功能进入后续范围，不是首版用户闭环的前置条件。

## 5. 对原挑战的局部复核与改稿映射

本次只复核受定位调整影响的节点和关系，保留原 C 编号。既有可靠性分支沿用上一轮证据，不重新展开审查。
模拟评审视角是独立开发者、执行与验收；不代表真实用户或独立专家已经完成效果验证。

### C01：范围指令向自然预期注入答案

原方案最佳回应（上一版 §3 C01）：
> “默认 intuition 只把区域/导航范围作为探索限制；含内部业务正确答案的指令须明确转为 guided 并在报告标注，不能混入自然预期效果表。”

检查：引文占比达标（回应正文全部为原话）；事实一致性通过（规划规则）；对当前功能 MVP 回应部分充分。
追问：独立开发者的首版是否需要一个自动分类指令与 guided 模式系统？当前实现又如何防止原始 focus 进入预期？
判断：边界必要，扩展模式可延后。J01/J02 推荐只保留范围定位通道，固定一般用户；实施后通过捕获请求检验内部答案未进入。
状态：T03 输入隔离与确定性回归已实现；真实模型语义效果尚待验收。

### C06：严格缺陷终稿会丢掉分析价值

原方案最佳回应（上一版 §6）：
> “报告至少列出 run 输入模式、被测环境/构建、探索预算和终止原因、判定失败/未覆盖范围、当前审核版本、确认问题清单、真实截图/技术信号、完整复现前置和步骤、回放状态及调查假设。”

检查：引文占比达标；事实一致性通过（规划内容）；对“保留认知落差原声”的回应部分充分。
追问：开发者认定按设计后，用户困惑是否还能进入交付物？如果只能清空该状态才能导出，分析与缺陷确认就被混为一谈。
判断：报告定位需要调整。R03/R04/R05 推荐新增全量 analysis 主入口，保留现有 confirmed gate；不同意或按设计均有备注与原始证据。
状态：报告规则已给出工程改稿，代码仍为 confirmed-only，新主入口待实施。

### C07：验证范围不应先吞掉功能交付

原方案最佳回应（上一版 §5.1）：
> “若主候选暂不可运行，可用固定版本的框架小应用验证机制，并单列“框架机制已验证、真实候选未完成”；不得据此宣称该复杂应用支持完整。”

检查：引文占比达标；事实一致性通过；对小应用验证路径回应充分，对首版顺序回应部分充分。
判断：沿用已有的小应用备选路径，按当前用户范围将它提升为 MVP 的主要验证对象。V01/V03 先做一般交互配对样例与一款真实小应用，真实模型与报告并行迭代。
状态：验证范围已按用户新约束调整；真实模型、成本和试用材料尚未取得。

修改映射：C01 → J01/J02 与范围说明；C06 → R03～R06 和 CLI/UI 结果入口；C07 → V01～V05 与阶段闸门。
其余历史挑战和原承诺见归档；岗位画像属于本次明确后置的范围选择，不伪装成既有功能缺陷。
