# N06 真实小应用候选与接入顺序

日期：2026-10-02。用户目前没有指定待测应用；本文件是候选建议，未克隆、部署或扫描这些项目，也不声明兼容性通过。

首轮建议先接 Linkding，然后接 Memos；TodoMVC 用于框架机制对照。排序是依据部署方式与可观察交互范围作出的工程判断，不是项目质量排名。

| 候选 | 已核对的项目事实 | 建议观察路径 / 价值 | 验收定位 |
|---|---|---|---|
| [Linkding](https://github.com/sissbruecker/linkding) | 自托管书签管理器，支持 Docker、标签、批量编辑、自动提取标题等；后端 Django | 新建书签、非法 URL 校验、保存反馈、标签检索与无结果；可核对异步元数据与用户可见结果是否混淆 | 第一款真实应用；先选单人收藏流程，不展开共享/SSO |
| [Memos](https://github.com/usememos/memos) | 自托管短笔记应用，支持 Docker；具备 Markdown、附件、搜索、标签和可见性控制，仓库标注 React | 新建/编辑笔记、保存反馈、标签/检索、私有与公开文案；观察受控输入、页面更新与陌生术语 | 第二款真实应用，扩大 SPA/状态与认知摩擦样本 |
| [TodoMVC](https://github.com/tastejs/todomvc) | 同一 Todo 功能在多个框架中实现；各示例可单独构建/服务 | 新增、编辑、勾选、筛选、清空已完成；同一交互对比 React/Vue | T02/T09 机制样例；不能单独代替 N06 的真实应用 gate |

项目功能与部署事实来自上表的维护方仓库，核对日期如上；实际接入时锁定 commit/tag 和构建产物，不使用会漂移的分支或镜像标签作为最终基线版本。

## 每款应用的首轮材料

目录约束：所有克隆、依赖、构建、配置和持久化测试数据都放在本项目 `examples/open-source/<项目>/` 内，已加入 gitignore；既有 `baselines/` 也只使用项目内目录。不得把示例搭到 `/tmp`、项目兄弟目录或全局工作目录。部署使用本地测试端口和项目内绑定数据目录，不使用项目外 Docker volume 存放示例数据；结果保存在项目内 gitignored 的 `artifacts/evaluation/`。

1. 记录版本、运行 URL、部署命令、重置方法和专用测试账号，使用本地测试数据；不扫描共享公开 demo 的写入流程。
2. 观察前写 5 条独立评估说明：明确反馈、合理校验、陌生术语、动作后禁用、缺反馈。不存在的场景如实标未覆盖，不为凑样例修改原应用后仍称原版结果。
3. 首轮用 URL 黑盒，只选择一条短流程和固定调用/动作预算；README、源码、评估说明不进入预期输入。需要登录时通过既有 `--login` 保存被测应用登录态。
4. 原版正常行为先跑；需异常配对时使用独立故障注入副本，保存注入差异与恢复方法。技术异常、用户摩擦、合理设计、模型误读分别记录。
5. 每个案例保留 scan/raw/图片、事前预期与依据、判断原文、T08 用量和未知费用；审核备注与评估分类分开。不删除失败/未决样本，不自动确认所有发现。

这套选择只扩大实际观察证据，不要求开发框架专用插件、岗位画像或团队功能。真实应用记录仍由 N06/K06/Q04 联合消费。
